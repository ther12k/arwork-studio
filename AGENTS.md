# AGENTS.md — arwork-studio (Color Duel Art Studio)

Single-user local artwork authoring studio: reference image + art-direction chat → approved
master → real vector paint + playable region geometry → review/play-test → versioned game ZIP.
The compiler, editor, validation and export work without any API key; AI features are optional.

## Layout

- `src/` — **Vite + React 19 frontend, port 3000** (shadcn/ui, Tailwind 4). Pure SPA, no server
  runtime: entry is `index.html` + `src/main.tsx` (no StrictMode on purpose), styles in
  `src/globals.css` (Tailwind-4 CSS-first config), Geist fonts via `@fontsource-variable/*`.
  App code: `src/components/studio/` (studio-page, canvas-workspace, left/right panels,
  `use-studio.tsx` state). `src/components/ui/` holds ONLY the shadcn components the app
  actually imports (14 files) — re-add individually via `bunx shadcn add` if needed, don't
  bulk-restore the template set. `src/lib/`: `studio-api.ts` (typed backend client),
  `detailed-board.ts` (runtime game board renderer), `svg-path.ts` (path flattening for the
  Node tool). There is no database anywhere; the Python backend persists to `workspace/` files.
- `mini-services/color-duel-studio/` — **Python FastAPI backend, port 8765** (the source of truth).
  `studio/pipeline.py` (vector compiler, all edit actions, QA, difficulty), `studio/app.py` (API +
  async job routes), `studio/models.py`, `studio/ai.py`, `studio/svg_master.py`, `studio/curves.py`.
  Tests in `tests/` (`test_pipeline.py`, `test_api.py`, `test_game_adapter.py`).
- `mini-services/ai-bridge/` — **bun service, port 8787**: OpenAI-compatible shim over
  `z-ai-web-dev-sdk` (`index.ts`).
- `Caddyfile` — gateway on **:81**: `?XTransformPort=<port>` query routes to that local port,
  default → :3000. This repo copy is the DEV gateway (proxies to the Vite dev server). The
  production Caddyfile is generated by `.zscripts/build.sh` and serves the static `web-dist/`
  directly (no Node process in the deploy container).
- `worklog.md` — append-only task log (Task ID / Work Log / Stage Summary per entry). The latest
  entries are the current state, known limits and next priorities. **Read the tail before working;
  append after meaningful work.**
- `upload/` — original delivery zips (reference only). `examples/websocket` — sandbox template,
  excluded from tsc/eslint. `.zscripts/` — dev/start/build scripts; `daemon.py` restarts the
  studio service.

## Architecture rules

- The frontend never calls :8765 directly. All backend calls use **relative paths through the
  gateway** with `?XTransformPort=8765` and the `X-Studio-Request: 1` header on every request
  (see `src/lib/studio-api.ts`). The backend enforces an origin check that compares hostnames
  ignoring the port.
- AI chain: browser → gateway :81 → Python studio → `AI_BASE_URL` → ai-bridge :8787 →
  z-ai-web-dev-sdk. No external OpenAI key. Every paid AI action requires an explicit confirm
  checkbox in the UI; without a key the controls render disabled, never simulated.
- Edit actions (draw/cut/pen/merge/recolor/node/playtest) are **async jobs**: body-level problems
  return 422, semantic validation errors surface as job failures with actionable messages — do
  not convert the routes to synchronous.
- **Revisions are immutable**: every edit produces a new revision + QA report + difficulty
  profile. Never mutate stored revisions (the playtest route patches the manifest difficulty block
  in place — that is the sanctioned exception).
- Regions must tile exactly (no gaps/overlaps); raster-partition builds tile the canvas exactly.
  Geometry-touching code (pen carve/rebuild `r-v-*`, cut `r-c-*`, pen `r-p-*`, node `r-n-*`,
  `partitionTolerance`) has subtle invariants — read the relevant `pipeline.py` branch and
  `docs/FORMAT.md` first.
- Edge semantics: `geometry.edges` distinguishes artwork boundaries (solid) from subdivision
  boundaries (dashed `3 2.2`). Exported numbered/linework SVGs must stay layer-identical to the
  runtime board: paint → masks → ink → edges → labels (asserted by tests, incl.
  `test_export_layer_order_matches_runtime`).
- The exported game bundle (format `color-duel-detailed-vector-1`) is self-contained; `regions.json`
  is mandatory for gameplay. Game runtime does not need the Python backend.
- Semantic object model: `objects.json` is an authoring layer (never in the lean runtime export,
  outside `contentHash`). Ownership is one-directional — objects own `shapeIds`, regions carry
  `objectId`; never store regionIds in object records. Object identity lives in the master SVG as
  `<g data-cd-object>` groups and is stamped by the AI scene planner before generation; edit
  actions preserve it via `_sync_objects_from_regions`. Auto-subdivide consumes per-object budgets
  (area × detailWeight × complexity, clamped, normalized); QA reports object issues as warnings.
- Generation orchestrator (Phase 2A): multi-step AI creation runs in transactional sessions
  (`GenerationSessionManager` under `sessions/{session_id}`). ScenePlan drafts support structured
  mutations (add/remove/update/reorder/difficulty). Healthy revisions are never mutated or corrupted
  during generation; failed/canceled sessions rollback cleanly; commit promotes the passed bundle
  atomically into `revisions/rev-*` with enriched `generation` provenance. Phase 2B adds the paid
  steps with explicit confirm gates: `/plan` (strict-JSON scene planning), `/generate` (one
  fragment per planned object via `svg_compose_from_objects`), `/regenerate-object` (replaces one
  object's shapes in the session master — objectId preserved, neighbours re-derived by recompile).
  Phase 2C adds `/reference-plan` (Use as Reference): the uploaded image is attached to the vision
  planning call and drafts a NEW semantic ScenePlan — the source is never traced; artwork is then
  generated natively via the same `/generate` step.
- Convert Artwork (Phase 2D, `/convert`): AI decides *what* the objects are (semantic ScenePlan,
  bboxes scaled from plan space into image pixel space); deterministic CV decides *where* pixel
  boundaries are (SLIC → tiny merge → Lab ΔE adjacent merge). Candidate segmentation is
  difficulty-independent (`CONVERT_CANDIDATE_BASE`) — changing difficulty must never alter the
  paint reconstruction (same `rc-*` shapeIds and path bytes; asserted by tests). Fidelity presets
  are real algorithm parameters: `segmentDensity` scales SLIC candidate count,
  `colorMergeDeltaE` drives the CIELAB adjacent merge, `curveTolerance`/`minComponentArea`/
  `paletteTarget` flow into BuildSettings. Raster paint paths carry stable shapeIds + `objectId`;
  the INITIAL converted revision emits `objects.json`. Quality gates score `visualFidelity` and
  `gameReadiness` independently and reject over-vectorization; geometry QA is enforced upstream
  by `emit_bundle`.
- Difficulty Optimization (`studio/difficulty.py`, Tasks 26+27): `optimize_gameplay_difficulty`
  moves ONLY the gameplay layer (regions, labels, object budgets, difficulty metrics) toward a
  requested tier — Convert runs it after reconstruction, and `POST /api/projects/{pid}/optimize`
  exposes it as a revision action (new immutable revision with the report in
  `manifest.difficultyOptimization` + `project.lastOptimization`; no-op reports create nothing;
  the route re-verifies the paint.json hash at byte level). The right-panel Optimize card is the
  artist-facing UI (tier selector, before/after, safe-ceiling reasons, "Artwork unchanged").
  Artwork invariants are hard: paint bytes + objects.shapeIds identical, geometry QA green every
  iteration, ≤3 deterministic iterations, merge-down never crosses objects (same objectId,
  palette ΔE order, readable labels), split-up reuses the object-budget subdivider with a doubled
  minimum so pieces never go microscopic. Quality outranks the tier label; unreachable targets
  report `safe-ceiling`/`best-safe-result` with reasons. Re-exposed sub-tolerance seams are
  absorbed via `partitionTolerance` re-measurement; the roundtrip pixel allowance scales with
  region count.
- Operation Resilience & Job Recovery (Task 31): Paid generation operations support `idempotency_key`
  with attempt tracking; same key collapses duplicate submits and replays completed results without
  resending or duplicating spend; conflicting payloads return 409; `/commit` replays the already-created
  revision. Cooperative cancellation (`POST /job/cancel`) stops workers before subsequent fragment
  calls and resets sessions cleanly to `draft_plan`. On process boot, in-flight jobs become `interrupted`
  (no automatic paid replay). Workers publish structured progress (`stage`, `completedObjects`,
  `totalObjects`, `currentObjectId`, `sequence`). Build provenance (`masterOrigin`) prevents a plain
  `/compile` from validating an outdated master against a swapped source.

## Conventions & hygiene

- Ports: gateway 81, Vite dev 3000, studio 8765, ai-bridge 8787 (all loopback-only; single-user
  MVP — never expose publicly).
- **Docker**: `docker compose up --build` runs the whole stack — `gateway` (Caddy serving the
  static build from the root `Dockerfile` + `docker/Caddyfile`), `studio`
  (`mini-services/color-duel-studio/Dockerfile`, workspace volume-mounted), `aibridge`
  (`mini-services/ai-bridge/Dockerfile`, `HOST=0.0.0.0` inside the compose network). Only :81 is
  published; studio/bridge get loopback-only debug ports. The container Caddyfile maps
  `XTransformPort=8765/8787` to the service names (upstreams differ from the dev repo Caddyfile).
- TypeScript path alias `@/*` → `src/*`. ESLint relaxes many rules (`no-explicit-any` off etc.),
  but `tsc --noEmit` is the real gate.
- Python: keep the pytest suite green; new backend behavior needs tests in the existing suites.
- Never commit `.env`, `db/`, `workspace/`, `download/`, `tool-results/`, `__pycache__/`, logs.
  CI's release-archive leak assertion fails the build if these appear in tarballs.
- Version is aligned across root `package.json`, backend `package.json` and `studio/__init__.py`
  `STUDIO_VERSION` (currently 0.3.1) — bump all together.
